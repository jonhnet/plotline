# Acceleration and carriage-travel timing experiments

**Neither proposed term earns a change to the live model.** Acceleration helps
the newly refitted model somewhat, but its predictions remain worse overall
than deployed v1 on excluded drawing families. The additional carriage-distance
term is effectively zero in the broad refits. With unrelated v1 coefficients
fixed, acceleration is disabled in every fold and the pooled fit.

[Tables, charts and full fit diagnostics](http://dev.iac.jonh.net:11088/build/timing-extensions-2026-11-06/)
are generated by `tools/plot_timing/extensions.py`. The committed
[numerical snapshot](timing-extensions-2026-11-06.json) retains coefficients,
source hashes, exact folds and per-drawing errors. No runtime code, live model,
service configuration, Pi state or physical plot was changed.

## What was tested

Use the same 14 complete captures from the
[earlier review](timing-validation-2026-11-06.md). Loading verifies the frozen
HPGL and trace hashes; missing or changed inputs fail the experiment rather
than silently changing its population. Captures remain subject to existing
retention. All plots use VS5, so no new speed-setting claim follows.

The baseline retains v1's effective 1,024-byte buffer and 32.03-ms sender
turnaround. Five existing coefficients may be refitted: drawing speed scale,
pen-up speed, lift/lower cycle, fixed pen-change overhead, and minimum vector
time. This matched control separates improvement from refitting alone from
improvement attributable to a new parameter.

The four broad candidates are:

- **Refit:** the original model family, with those five coefficients refitted.
- **Acceleration:** add one finite acceleration parameter to the refit, using
  the existing trapezoidal-motion and geometric corner-speed approximation.
- **Carriage:** add one nonnegative seconds-per-metre coefficient for carriage
  travel at pen selection.
- **Both:** fit both additions together.

Finite acceleration is bounded to 500–10,000,000 mm/s² and starts from 2,000,
10,000 and 100,000. The original disabled-acceleration case is also an explicit
candidate. Carriage time is bounded to 0–100 s/m, including a separate zero-term
case. Extended families can always choose their simpler nested model. Multiple
starts and nested cases are selected using training error only.

The carriage feature is a **proxy**, not measured mechanism travel. The archived
HP-GL coordinate diagram (`research/controller/manual-pages/7585-axes.png`,
printed page 7) shows +Y across the carriage toward the control panel, with the
carousel on the opposite side. At SP, take distance from the last commanded Y
to the carousel-side edge of the observed drawable window. Charge two legs
for an exchange, one for parking or picking up from an empty holder. Repeated
selection of the same slot has no term. The unknown first carriage position is
omitted, matching v1's initial-move limitation.

The actual distance off the drawable sheet is unrecorded; the fixed overhead
must absorb it. That is approximate, especially when pickup/parking and exchange
have different leg counts or loading offsets differ. The result tests this
particular low-parameter feature; it does not show that physical carriage travel
takes zero time. It does not infer a full mechanical path from logical HPGL.

## Validation and fitting objective

Exclude one **entire family** at a time:

| Family | Captures |
| --- | --- |
| Maps | Snoqualmie, Ravenna, Paine |
| Screened images | IMG_0456, Shrek/Felicia, Shreksgiving |
| Monochrome line art | Principal's office |
| Sierpiński | Both sizes |
| Branching | Branching plant |
| Hilbert | Hilbert curve |
| Calibration | All three calibration sheets |

Related variants never appear on both sides of a fold. There are seven such
folds and one pooled fit on all inputs. The latter is an in-sample diagnostic,
not validation. The deployed v1 control originally used Snoqualmie, so its map
scores are not all independent tests of that original model.

Each family has equal training weight, divided equally among its drawings.
Each longer drawing allocates half its squared-error weight to total duration
and half to mean squared local timing error. Local intervals span 32 packets
(about 16 KiB), starting after the first 32 packets to avoid the unknown initial
move. Errors are divided by observed interval duration, with a fixed 10-second
floor. Short drawings without these intervals use total duration alone.

The same objective, bounds, buffer and sender pacing apply to every broad
candidate. This objective deliberately includes short sheets and completion
tails so that the pen-change hypothesis is tested, unlike the earlier
long-drawing-only guarded-window refits. Fixed-pacing predictions do not use an
omitted drawing's observed sender gaps. Complete OA/OS replies provide duration
when available; Snoqualmie and Ravenna retain their feeding-only comparison.

**This is exploratory validation.** These drawings have already been examined
in previous reviews and informed the proposed hypotheses. Whole-family exclusion
prevents direct fitting to the test family's timing but cannot make this fresh
prospective evidence. The method and broad model families were fixed before
running these fits. Restricted checks below were added afterward and are labeled
accordingly; none of these results justify claiming an unseen-data improvement.

## Results

Mean absolute duration errors across the 11 artwork captures (maps included):

| Model | Mean absolute error |
| --- | ---: |
| Deployed v1 | **1.59%** |
| Matched refit without additions | 2.72% |
| Refit plus acceleration | 2.55% |
| Refit plus carriage travel | 2.72% |
| Refit plus both | 2.55% |

The broad acceleration fit improves on its matched refit control, but does not
beat deployed v1 overall. Illustrative excluded-family results:

| Plot | Deployed v1 | Refit plus acceleration |
| --- | ---: | ---: |
| IMG_0456 | −2.78% / −8:36 | +0.83% / +2:33 |
| Shrek/Felicia | +1.13% / +1:18 | +4.88% / +5:36 |
| Shreksgiving | +0.90% / +1:00 | +5.11% / +5:41 |
| Smaller Sierpiński | +5.17% / +10 s | +3.21% / +6 s |
| Hilbert | −1.79% / −7 s | −6.66% / −26 s |

Positive errors are overestimates. These are predictions from fits excluding the
row's entire family, not predictions from the pooled coefficients.

The finite acceleration estimates are approximately 12,000–35,000 mm/s² across
folds. The pooled acceleration fit is about 19,883 mm/s², while pen-up speed
reaches the 1,000 mm/s optimization bound. These compensating effective
parameters should not be read as measurements of the plotter's acceleration or
unloaded carriage speed.

The carriage coefficient is effectively zero in broad refits (at most a few
milliseconds per metre); the combined model brings no meaningful gain over
acceleration alone. The calibration family still has about **19.45%** mean error
with acceleration, compared with **20.83%** for v1. It does not solve the
short-sheet discrepancy.

## Restricted follow-up checks

To check whether broad parameter refitting obscured a useful small addition,
freeze unrelated v1 coefficients and repeat the same family exclusions:

1. Fit **only acceleration**. Every fold, and the pooled fit, chooses the
   disabled term. The existing coefficients leave no supported additive
   acceleration correction under this objective.
2. Fit **only fixed pen-change overhead**, as a matched control.
3. Fit **fixed pen-change overhead plus carriage distance**. The pooled fit
   chooses roughly 1.03 s fixed overhead and zero added distance cost. Most
   folds do likewise. Excluding calibration permits a much larger distance
   coefficient, showing that the estimate depends on which geometry is present;
   it is not a stable globally supported correction.

These checks reinforce retaining v1 rather than adding complexity now. Any
future refinement needs fresh complete drawings and a frozen candidate before
inspection, with short-sheet and long-artwork performance reported separately.

## Reproduce and verify

```sh
OPENBLAS_NUM_THREADS=1 PYTHONPATH=tools build/timing-venv/bin/python \
  -m plot_timing.extensions --workers 3 \
  --output build/timing-extensions-2026-11-06

build/timing-venv/bin/python -m unittest discover -s tests \
  -p 'test_plot_timing*.py' -v
```

The environment is pinned by `requirements-timing.txt`. The offline development
command uses Linux fork workers to share read-only parsed captures. It has no
production dependency and cannot send plotting commands. `--fold` can run one
family or the pooled diagnostic; the default runs all folds.

Fourteen tests pass. New tests cover across-sheet direction and units, coordinate
translation, repeated selections, pickup/parking/exchange leg counts, unknown
initial position, invalid geometry, exact v1 behavior at zero added cost, family
weighting under repeated related drawings, and the ability to disable an added
term when the baseline is exact.

Outputs include `comparison.png`, `comparison.svg`, `comparison.csv`,
`index.html`, full `results.json` with multistart diagnostics, and compact
`snapshot.json`. The committed numerical snapshot is a copy of the latter.
