# Timing validation on Ravenna and Paine Field

**Keep the deployed `hp7585-snoqualmie-v1` coefficients.** Both independent
drawings are within 1% overall. Refitting the same six-parameter family improves
one omitted drawing but worsens the other; there is no consistent improvement
to deploy. This analysis changed no service, hardware, or model coefficients.

[Charts and full numerical results](http://dev.iac.jonh.net:11088/build/timing-validation-2026-11-04/)
are generated by `tools/plot_timing/evaluate.py`.

## What was captured

The spool contains two full drawings beyond the original Snoqualmie calibration:

| Drawing | Attempt | Started (UTC) | Evidence |
|---|---|---|---|
| Ravenna Park | `d01d3b55-b760-4cf6-9e64-5fd2dd613330` | Nov 3, 03:57 | Complete feeding trace; run just before estimate installation; no automatic finish timestamp |
| Paine Field | `aada5cc2-04fe-43d8-8952-5b52c49b1370` | Nov 4, 02:46 | Saved pre-plot prediction, complete feeding trace, OA/OS-confirmed completion |

These are the additional real plot captures available at review time. They had
already streamed back to `controller/state/jobs/plots/` on dev. Other traces
under worktree build directories are fake-device integration-test artifacts.

Ravenna has 970,576 prepared bytes / 78,256 commands / 9,592 Pi samples. Paine
has 1,009,524 prepared bytes / 80,476 commands / 9,981 Pi samples. Both are at
VS5 and FS4, with all prepared bytes acknowledged, closed traces, no transport
errors, no pause/cancel/resume writes and no truncated records. Paine's two
terminal completion queries are validated and excluded from drawing offsets.
Exact HPGL/trace hashes and capture integrity summaries are in `results.json`.
The original unique inputs remain in the existing backup selection.

## Unchanged model results

| Drawing / measurement | Model | Observed | Error |
|---|---:|---:|---:|
| Snoqualmie, feeding (original calibration) | 61:29 | 61:59 | −30.04 s / −0.81% |
| Ravenna, feeding (independent drawing) | 34:25 | 34:09 | +15.54 s / +0.76% |
| Paine, feeding (independent drawing) | 39:36 | 39:29 | +6.83 s / +0.29% |
| Paine, OA/OS-confirmed finish | **39:42** | **39:32** | **+10.00 s / +0.42%** |

The original model is applied to Ravenna afterward with no coefficient changes.
Paine's recomputed prediction matches the estimate actually saved before sending,
including its exact prepared-file hash. Values above round durations to seconds;
percentages use the unrounded values.

Completion is measured from the trace's start, excluding the initial connection,
paper query, and preparation. OA's complete reply arrived at 2,372.062058 seconds;
OS at 2,372.134149 seconds. The retained confirmation is position
`[-6812, -2993]`, pen up, status 26. These are reply timestamps rather than an
independent physical motion sensor; they include the short query/serial latency.
Split replies count only when the line terminator arrives. The comparator checks
the replies against the saved completion record instead of using a rounded wall
clock finish time or the subsequent serial close.

Paine's modeled tail was 6.42 seconds. From the final prepared-write
acknowledgement to OA was 3.15 seconds, and to OS 3.22 seconds. The roughly
three-second excess is immaterial to the overall estimate and does not justify
a new tail-specific parameter from one example.

Replaying the unchanged remaining-time curve at Paine's recorded packet
boundaries gives median absolute error **12.58 seconds**, 95th percentile
**19.18 seconds**, and maximum **21.39 seconds**. This replay uses Pi queue-empty
boundaries; live acknowledgements follow them by a short transport delay. It does
not reconstruct every browser poll or the UI's minute rounding. Cumulative feed
errors reach roughly 30 seconds partway through the job, so total error alone
still does not describe every moment of the countdown.

## Refit experiment

Use the same model family and parameter bounds as v1. Fix acceleration at the
selected no-correction limit and sender turnaround at v1's 32.03 ms. Optimize
the other five continuous coefficients and profile buffer capacity over
256–4,096 bytes, then refine at 32-byte spacing around the best candidate.

Fit calibration windows only, using the original guarded 64-KiB block split.
Normalize residuals by the square root of the number of calibration windows
per drawing, so the longer Snoqualmie plot does not dominate. Crucially, for
each row below, omit that **entire drawing** from the refit. Evaluation uses
fixed sender turnaround and HPGL alone, not the omitted trace's measured gaps.

| Entire omitted drawing | Existing v1 feed error | Refit on other two feed error |
|---|---:|---:|
| Snoqualmie | −0.81% (v1 calibration result) | −0.89% |
| Ravenna | +0.76% | +0.32% |
| Paine | +0.29% | **−1.22%** |

The Paine finish prediction likewise worsens from +0.42% to −1.15% when refitted
without Paine. New coefficients therefore do not consistently predict an
independent drawing better. The profile still prefers about 1 KiB of effective
buffer and about 18 ms minimum vector time; pen-up and pen-change coefficients
continue to vary substantially between fits.

For comparison, a pooled fit using calibration blocks from all three drawings
has feed errors −0.91%, −0.59%, and −1.08%, respectively. Its Paine finish error
is −1.00%. These are in-sample diagnostics, not another external validation.
Some short-section residuals improve slightly while overall predictions worsen.
The complete candidate coefficients, buffer profiles, audit-section statistics,
and all-drawing scores are saved in `results.json`. No candidate is promoted.

## Reproduce

Use the isolated environment from `requirements-timing.txt`:

```sh
PYTHONPATH=tools build/timing-venv/bin/python -m plot_timing.evaluate \
  controller/state/jobs/plots/88cb8e31-bf26-46e0-8f7f-bb11bba67294 \
  controller/state/jobs/plots/d01d3b55-b760-4cf6-9e64-5fd2dd613330 \
  controller/state/jobs/plots/aada5cc2-04fe-43d8-8952-5b52c49b1370 \
  --output build/timing-validation-2026-11-04

build/timing-venv/bin/python -m unittest discover -s tests -p test_plot_timing.py -v
```

Outputs are `index.html`, `results.json`, and `validation.png` / `.svg`.
Tests additionally cover fragmented completion replies, leading CR/LF,
missing terminators, mismatched status, and keeping finish/tail comparisons
on the service's monotonic clock. The fitter never contacts the plotter.
